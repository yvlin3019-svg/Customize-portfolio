# カスタマイズ実績（カスタマイズ商品の集計システム）

[繁體中文](README.md) | [English](README.en.md) | **日本語**

店舗のカスタマイズ商品を対象にした、**日次の売上計算と月度集計**のシステムです。毎日の入力が終わったら当日合計をワンタップでコピーし、そのまま LINE に貼って報告できます。月末には、スタッフごとの件数、デリート／マルチの比率、品相の内訳を自動で集計し、「丸＝シール」の形で表示します。これまでの手計算、手作業の表づくり、シール貼りを置き換えるものです。

## 背景：解決したい課題

店舗のカスタマイズには **マルチ（定価）** と **デリート（割引）** の2種類があり、マルチはさらに Tabby、シューズ、その他などの品相に分かれます。これまでの作業の流れは次のとおりでした。

- 毎晩、当日の件数・unit 数・税抜金額を**手で計算**し、決まった形式の文章にまとめて LINE で報告する
- 月末に、スタッフごと・週ごとのマルチ／デリート件数と、マルチの品相を**手書きで2枚の表にまとめる**
- 各スタッフが、自分の担当した品相に対応する色の**シールを表に貼る**

この流れには、いくつかの問題がありました。

1. **時間がかかり、ミスも起きやすい**：税込から税抜への換算や unit の合計を毎日手で計算するため、計算ミスが起こりがちです。
2. **シールを貼り忘れる**：貼り忘れは月末の集計のずれにつながり、あとから確認するのも困難です。
3. **進捗が見えない**：月度目標（例：160 件）にどれだけ届いていないかが月末までわからず、月の途中でペースを調整できません。
4. **毎月表を作り直す必要がある**：会社独自の会計カレンダー（例：FY27 は 6/28 開始、P4 は 9/27〜10/31）を使っているため、月度ごとに日数も週の区切りも異なります。

## システム構成

システムは3つの部分に分かれており、**店舗の実際の役割分担に合わせて設計**しています。

| 部分 | 使う人 | 内容 |
|---|---|---|
| **日次入力** | 毎晩の締め担当 | 当日の各明細をすばやく入力すると自動で合計され、LINE 用の文章をワンタップでコピー |
| **カレンダー** | スタッフ全員 | 日付を開き、自分が担当した商品に担当者と品相を設定 |
| **月度集計** | 店長／全員 | 目標に対する進捗、スタッフ別の実績、週ごとの表を確認し、レポートを出力 |

このほか**設定**ページで、スタッフ名簿、月度と目標、品相とシールの色を管理できます。

設計の中心にあるのは、**「入力」と「担当の割り当て」を分ける**という考え方です。締め担当は数字を正しく入力することだけに集中でき、1件ずつ誰が担当したかを把握する必要はありません。担当者と品相は、各スタッフがあとから自分で設定します。そのため、ほかの機能がいくら増えても、日次入力はもとの計算ツールと同じくらいシンプルなまま保てます。

## 機能一覧

### 進捗カード

すべてのページの上部に、**現在の月度・期間・目標件数・今日までの件数・達成率**を進捗バーとあわせて表示します。開いた瞬間に今の状況がわかります。

### 日次入力

<img src="screenshots/daily-desktop.png" width="720" alt="日次入力（PC）">

- デリート／マルチを選び、件数・パーツ数・**税込金額**を入力すると、**税抜金額に自動換算**します（10%／8% に対応）。
- 当日合計は LINE 報告の決まった形式に自動で整えられ、**ワンタップでコピー**できます。
  ```
  6件15unit ¥232,000（マルチ4件10unit ¥193,000）M2件
  ```
- モノグラミング（M）は、1日ごとの件数として別に記録します。
- 画面下の「当日の明細」で報告前に最終確認ができ、誤って削除しても「元に戻す」で復元できます。

### カレンダー

- 月度単位のカレンダーで、**各マスには日付とその日の件数だけを表示**します。画面がすっきりし、スマートフォンでも1画面で月度全体を見渡せます。
- その日に**担当者が未設定の明細、または品相が未設定のマルチの明細があると、マスの右上に赤い点**が表示されます。
- 日付をタップすると、その日の明細を編集できます。
  - 担当者の設定と品相の選択（ボタンの色がシールの色）
  - 未設定の明細は**自動的に上にまとめて表示**され、開いてすぐに対応できます
  - 「修正」の中には、種類の切り替え、スタッフ私物の指定、件数や金額の修正、そして**複数件の明細を1件ずつに分割**する機能があります（1件の明細に担当者や品相の違う商品が含まれている場合に使います）

### 月度集計

<img src="screenshots/monthly-desktop.png" width="720" alt="月度集計（PC）">

- **3つの進捗指標**
  - **達成率**：完了件数 ÷ 目標
  - **今日までの目標**：毎日均等に進めた場合、今日までに何件できているべきか（進捗バーの赤い線）。今が先行しているか遅れているかがひと目でわかります
  - **必要ペース**：残りの日数で目標を達成するには、1日あたり何件必要か
- **累計の推移グラフ**：実線が累計実績、点線が目標ラインで、その差が進捗の差になります。
- **スタッフ別**：各スタッフのマルチ／デリート件数を積み上げ横棒グラフで表示します。
- **表1（マルチ／デリート）と表2（マルチの品相）**：店舗で使っていた2枚の紙の表を再現し、週ごと（日曜〜土曜）に集計します。**丸1つが1件、つまりシール1枚**にあたり、色もシールの色と同じです。数字よりも積み上がり具合がわかりやすくなります。
- 担当者が未設定の件数は「担当未設定」として別の行に表示されるため、集計から漏れることはありません。ページ上部にも注意が表示されます。

### 出力

<img src="screenshots/report.png" width="720" alt="印刷用ファイル">

| ボタン | 内容 |
|---|---|
| **印刷用ファイル** | A4 横の月度レポート：スタッフごとの金額、件数、デリート／マルチの件数と比率、各品相の件数と比率 |
| **集計表 CSV** | レポートと同じ内容の CSV。Excel でそのまま開けます |
| **明細 CSV** | 1件ごとの元データ。照合やバックアップに使えます |

画面上では丸で表示し、**出力時には集計しやすい数字に切り替え**ます。CSV は Excel で日本語が正しく読める形式で保存されるため、文字化けしません。

### 設定

<img src="screenshots/settings.png" width="240" alt="設定">

- **スタッフ**：タグ形式で並び、**ドラッグで順番を入れ替え**られます。名前をタップすると「非表示」と「削除」が表示されます。
- **月度と目標**：各月度の名前、期間、目標件数を設定します。**週は日曜〜土曜で自動的に区切られる**ため、4週・5週どちらの月度にも正しく対応します。「＋次の月度」で、前の月度に続く新しい月度を自動で作成できます。
- **品相とシールの色**：自由に追加、色の変更、並べ替え、削除ができます。

## 設計のポイント

- **データが失われない管理方法**：スタッフが退職したときは「非表示」にすると、選択肢には出なくなりますが、**過去の記録やレポートには名前が残ります**。品相も同様で、削除しても過去のデータが消えたり表示が崩れたりすることはなく、「未設定」に戻るので設定し直せます。
- **設定漏れを防ぐ3つの仕組み**：赤い点、未設定の明細を上に表示、月度集計ページの注意表示。これらで全件に担当が付くようにし、「シールの貼り忘れ」のリスクを置き換えています。
- **誤操作の防止**：削除は元に戻せます。月度の削除のように影響の大きい操作は、2回押して確定する仕組みです。
- **スマートフォン優先**：すべてのページをスマートフォンでの利用に合わせて調整しています。明細は1件1行、タブは横スクロール不要、カレンダーは1画面に収まり、入力エリアも上下に行き来せずに使えます。
- **リアルタイムの共同編集**：データは共有データベースに保存され、誰かが入力するとほかの人の画面にもすぐ反映されます。編集権限のない人には自動的に閲覧専用の画面が表示されます。
- **ダークモード**：スマートフォンのシステム設定に合わせて自動で切り替わります。
- **キーボード操作**：PC では矢印キーでもスタッフや品相の順番を入れ替えられます。

## 技術的なポイント

- **1つの HTML ファイル**で、HTML／CSS／JavaScript のみで作成しています。フレームワークやビルドツールは使っていません。
- 累計グラフ、丸の週表、進捗バーはすべて SVG と CSS で**独自に描画**しており、グラフ用ライブラリに依存していません。
- 配色は CSS 変数で管理し、ライトテーマとダークテーマの両方に対応しています。
- データの保存には **Claude Artifacts の共有データベース**を、ファイルの保存にはそのダウンロード機能を使っています。

| ファイル | 説明 |
|---|---|
| `customize-system.html` | システム全体（日次入力＋カレンダー＋月度集計＋設定）。共有データベースを使うため、Claude Artifacts 上で動かす必要があります。 |
| `daily-calculator.html` | 日次計算だけの単独版。データは各自のブラウザに保存されるため、**アカウント不要で、どのウェブスペースにも置けます**。現在、店舗で実際に使われています。 |

## 私の役割と開発の進め方

このシステムは、AI（Claude）と協力して作りました。私が担当したのは次の部分です。

1. **課題の発見**：日々の業務の中から、手計算・表づくり・シール貼りといった負担の大きい部分を見つけ出しました。
2. **ルールの整理**：店舗のカスタマイズのルール（マルチ／デリート、品相、会計カレンダーの月度と週、LINE 報告の形式、税込と税抜）を明確な文章にまとめ、AI に実装を依頼しました。
3. **細部の調整**：実際にスマートフォンで操作しながら、文字の大きさや比率、どの情報を画面に残してどれをしまうか、1行にどこまで収めるかなど、1つずつ修正を依頼し、画面をシンプルに保ちました。
4. **問題の予測**：実際の運用で起こりうる問題を AI に洗い出してもらい、どれに対応するかを判断しました。たとえば「スタッフが退職したら過去の記録は消えてしまうのか」という疑問から非表示機能が、「1件の明細に2人分の商品が含まれていたら」という疑問から分割機能が生まれました。

## 制約と今後の改善

**現状**：日次計算の部分（`daily-calculator.html`）は、すでに店舗で使われています。月度集計を含むシステム全体は、データベースが個人の Claude アカウント上にあり、スタッフ一人ひとりがアカウントを持って招待を受ける必要があるため、店舗全体での実運用テストにはまだ至っていません。個人でのテストでは問題なく動作しています。

**今後の改善案**：

- **データベースを店舗や会社が管理できるサービス（Google スプレッドシートなど）に移す**ことで、システム全体をどのウェブスペースにも置けるようにし、スタッフが追加のアカウントを持たなくても使えるようにする。
- **モノグラミングの件数をスタッフごとに記録する**。現在は店舗全体の1日の合計のみを記録しています。
- **変更履歴を残す**。数字に食い違いがあったとき、誰がいつどの明細を変更したかを追えるようにする。
- **返品・キャンセルに対応する**。現在は該当する明細を削除するしかありません。
- **担当者の一括設定**。その日の商品をすべて同じ人が担当した場合に、未設定の明細を1件ずつではなくまとめて設定できるようにする。
